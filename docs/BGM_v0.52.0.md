- 首次實際攻擊：attack通過技能與準備檢查、確認有目標及實際攻擊資源後，於命中判定前切B2；落空仍算出手。
- 敵人strike在有效目標與彈量確認後啟動；foeHit補上隊長集火共用路徑；foeVsFoe處理敵人互打；ambushQte於撲擊開始切曲。縱火客投瓶、玩家燃燒瓶、開場pendingBurn、發瘋打隊友及實際攻擊型環境對策另補掛點。
- 偷襲與雙持、角色攻擊技能沿attack共用；準備型技能與非攻擊行動不觸發。
- B2使用完整64.53779秒OGG原檔循環；MP3採原素材備援。只於首次切入從0開始，後續攻擊不重播。

- BGM與SFX開關獨立。固定三個Audio元素，淡化結束只留一首；背景／離頁全部暫停；失敗優先換MP3，兩種格式皆失敗則退回探索。播放受阻後可由下一次操作恢復。

## 多人與存檔

- G.fight.musicId為本場識別、musicStarted為本場是否已出手；只有本場戰鬥資料新增兩個欄位，不寫玩家永久能力或跨局記錄。
- 房主在首次攻擊前送bgm事件，隊友由原pump佇列在攻擊事件前處理；核對局別與場次，重複事件不重啟。快照、存檔與房主交接保留已出手標記。
- 本機已進battle時，同場較舊的未出手快照不使曲目倒退；新場識別清除該本機標記。
- 舊存檔缺標記時，首次恢復採遭遇曲，直到下一次實際出手。無法從舊資料確知首攻，避免憑先攻回合數推測。

## 既有規則注意

原遊戲handAtk會將空彈槍械／缺箭弓弩自動改為近戰敲擊。這是實際攻擊，仍應切曲；不改成禁止攻擊。卡彈、未上弦、有彈但不足連射、瞄準準備與缺少打火機的投瓶不切曲。若未來另做單純射擊失敗分支，須維持不切曲。

本次沒有更動原攻防、QTE、傷勢、耗彈、劇情及玩家顯示規則；只依主人核准新增音樂管理與本場同步標記。

雲端首輪完整run_all通過，配樂長度專項失敗：Python簡易伺服器未支援Range，瀏覽器以位元率估計OGG長度（遭遇6.396／戰鬥57.664秒），音檔實際解碼仍為8.067／64.538秒。正式Pages已確認回應206及Accept-Ranges。配樂專項改用tools/bgm-http.cjs模擬正式Range服務並驗證206；長度斷言維持原標準，既有tests/不動。技術依據：https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Configuring_servers_for_Ogg_media 。
