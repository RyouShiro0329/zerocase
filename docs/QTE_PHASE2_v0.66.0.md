## 3. QTE 呼叫位置（全部）
- `qte()`（qte.js）只剩三個入口：`qteHit`（戰鬥，只有 infected/撲倒、predator/飛撲，用敵種／招式名稱的明確清單；tests/qte-phase2 掃 MOVES 證明）、`storyQte`（劇情結果的 `qte` 欄位：**目前資料裡 0 筆**，入口保留給之後的火場等專屬設計）、密碼輸入 `askCode`（不是 QTE，共用連線通道）。
- 拿掉：`ambushQte`（偷襲開場）、`hazard` 裡的 QTE（改背景豁免）。
- 沒有任何全域頻率限制：同一輪不同敵人各自可以撲倒／飛撲，同一個人下一輪也可能再遇到，只看招式原本的權重與冷卻。技術上 QTE 是一個接一個 await，同一人不會疊兩組。
- 原 QTE 引擎沒改：527ms／格、普通困難 3～4 格、真實 4～6 格、整組倒數不重置；格子出現前原本就有 0.5～1 秒隨機停頓（倒數從第一格出現才開始），這是 v0.49.0 起原本的引擎，沒加也沒拿。新加的只有 `o.now`：戰鬥瞬間 QTE 前把還在逐字打的字補完，不等打字。

- 敵方突襲：`startFight` 把突襲者標 `f.amb`：預設只有第一隻（舊 ambushQte 本來就是挑 `aliveF()[0]`）；事件寫 `fight.amb:'all'` 才全體（只限同陣營）。擲完先攻（**沒有 +4**）後 `ambushAct` 讓突襲者照牠平常的方式 `foeAct` 一次（照常選招式、擲命中，不必中；選到撲倒照樣是當下 QTE），`F.ambDone` 先記好，換房主不會再動一次；之後照擲好的先攻開始第 1 回合。**現有 104 筆 `mode:'ambush'` 都沒有明確集體設定，主人選維持全部單一突襲者**（候選：S0、P4、SB0、OBw）。
- 我方先制：照常擲先攻 → `sneakOpen` 挑敏捷最高（statMod，含傷勢、骨折後的實際敏捷）的人（同分比本場先攻，再照隊伍順序）→ 只有他能下指令，**任何戰鬥行動都可以**（攻擊、技能、雙持、對策、道具、防守…），照常擲骰（會落空、會爆擊）；行動不成立時和一般回合一樣改普通攻擊；不占他的回合 → 照擲好的順序開始第 1 回合。多人：其他人等；強制倒數到了沿用原本的自動普通攻擊；房主換人時還沒選就重新開放、已經在結算就不補；還沒擲先攻就換房主，由 `openStart` 補跑整個開場。
