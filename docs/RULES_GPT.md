# 給 GPT／Codex 的專屬規則（零號病例）

這是長期更新的遊戲，主人要的是**每一版都穩、不改壞**。先讀 `AGENTS.md`、`docs/AI_WORKFLOW.md`，這份是在那之上要多注意的地方。

## 一、開工順序（每次都一樣）
1. 從最新的 `main` 開新分支，不要接在舊分支上做。
2. 讀 `docs/VERSIONS.md` 最上面三行和 `更新說明.txt` 最上面那一版。版本可能是 Claude 剛發的，Build 要接著加一。
3. 把主人的要求拆成清單，做完逐條對照。
4. 下面這些情況，**停下來寫方案給主人選，不要直接做**：
   - 新系統，或改核心規則；
   - 刪內容，或改劇情走向；
   - 要求有兩種以上合理做法；
   - 會讓舊測試失敗。

   如果工具不能即時問問題，就把 2～4 個方案寫在回覆或 PR 裡，這次只做確定的部分。

## 二、GPT 最容易出錯的地方
- **用語**：
  - 遊戲文字和文件都用**台灣繁體中文用語**，不能有簡體字。
  - 常見錯誤：

    | 不要寫 | 要寫 |
    |---|---|
    | 視頻 | 影片 |
    | 激活 | 啟用 |
    | 默認 | 預設 |
    | 信息 | 資訊／訊息 |
    | 菜單 | 選單 |
    | 用戶 | 玩家／使用者 |
    | 點擊 | 點／按 |
    | 質量 | 品質 |
    | 反饋 | 回饋 |
    | 屏幕 | 螢幕 |
    | 暴擊 | 爆擊 |
    | 優化 | 改善 |
    | 項目 | 專案 |
    | 鼠標 | 滑鼠 |

  - guard 測試會抓一部分，抓不到的也不能寫。
- **改寫太多**：
  - 不要重寫整段劇情、整個函式或整個檔案。
  - 不要改格式、縮排、引號風格，也不要把長行拆開。
  - 不要把 `index.html` 拆成多個檔案（Claude 有自己的切檔工具，靠模組第一行標題）。
- **假裝測過**：
  - 沙盒沒有網路或沒有 playwright 時，瀏覽器測試和長路線測試寫「未測試（原因）」，**不能寫成通過**。
  - Node 測試一定要跑。
- **自創設定**：
  - 不加新角色、新陣營、新地名、靈異事件、喪屍殭屍。
  - 不加台灣在地事物，舞台是 2038 年的美國城市。
  - A.C.R.U. 在一般文字只寫「穿黑色制服的人」。
- **幫玩家把話說完**：
  - 選項小字不寫後果、數字、去處、時間，詳見 `AI_WORKFLOW.md` 的「2026-11-20 補充」。
  - 噪音、警戒、善惡值這類隱藏數值，都不寫在選項上。

## 三、改 index.html 的方法
- 所有程式在同一個 `<script>`，共用全域範圍。新增任何名稱前先搜尋有沒有撞名。
- 用搜尋找位置再局部修改，替換前確認舊字串在檔案裡只出現一次。
- 節點的 `go`／`next` 指到的節點要存在。改旗標名稱或存檔結構，要在 `migrateG` 加舊存檔轉換。
- 不要碰：
  - 兌換碼：程式裡只放雜湊；
  - Claude 的 artifact 連結；
  - 敵人立繪：只用主人提供的美術；
  - QTE 規則：只靠玩家反應。

## 四、測試與發布（照順序）
1. `node --test tests/*.test.cjs` 全部通過。`tests/guard.test.cjs` 永遠不改。
2. 新功能或修正補 1～3 個聚焦的測試，放在既有的測試檔。
3. 遊戲文字有新字：
   - 先 `pip install fonttools brotli`，再跑 `python3 tools/make_font_subset.py`；
   - 把 `index.html` 兩處 `fonts/tw-kai-game.woff2?v=` 換成新字型 SHA-256 的前 8 碼。
   - 沒有新字就不要跑。
4. 更新：
   - `const ZC_VER=`：版本、Build +1、Asia/Taipei 時間；
   - `更新說明.txt` 最上面；
   - `docs/VERSIONS.md` 表格最上面；
   - `MANIFEST.json` 重算雜湊，有新檔案也要加進去；
   - 然後 `python3 verify_release.py` 要通過。
5. 環境允許就跑 `bash tests/run_all.sh`，一次只跑一個。
6. 開 PR，說明照 `AGENTS.md` 的格式，並列出碰到的設計規則。**不要自己合併**，主人會在 GitHub 上合併。

## 五、回報給主人
- 用中文，短。
- 內容：改了什麼、測試結果（通過／失敗／未測試＋原因），以及有沒有碰到原本的設計規則。
- 手機一律寫「待主人實機驗收」。

## 六、攻擊特效的展示、確認與整合（主人 2026-11-21 定案）
1. **先讀目前遊戲**：從最新 main 讀攻擊流程、既有特效圖集、實際尺寸算法、原音檔、音量與播放時機。比較風格必須打開原圖，不靠記憶。
2. **記錄已定案的條件**：適用武器、目標位置、方向、大小、筆觸／配色／亮線、格數、命中格、收尾方式與音效。主人只要改其中一項，就只改那一項；「重畫」不代表可以換風格、方向或動作。
3. **先展示再整合**：製作十二格圖集，再放進目前遊戲介面做有聲預覽；能提供影片就附影片。預覽必須在實際敵人卡、血條位置演示，不能只給離開介面的特效圖。手機離線 HTML 必須自帶必要圖像、字型與原音效，有明確的重播按鈕。
4. **聲音對動作**：以遊戲目前實際音檔的主要撞擊段對齊刺中／砍中／敲中的畫面與血條更新。除非主人另外要求，不換原音效、不變速、不變調、不裁尾音、不擅改音量。沒試聽或沒看到連播就如實寫未測試。
5. **照主人回饋局部修改**：已認可的風格與前幾格保留；區分「整個輪廓透明度淡出」與「亮線斷裂、紅黑殘影碎散消失」。不得把穿刺做成飛過敵人的光束，不得自行加入回抽。
6. **明確同意才部署**：主人說「就這個、開始實作部署」後，將核准預覽的素材、尺寸、方向、動作與收尾接入真實攻擊；預覽用固定血量、固定骰點、測試按鈕不得進正式遊戲。已有本輪明確部署授權時一路完成，不重複問是否合併或部署。
7. **完整驗收**：原傷害、耐久、落空、其他攻擊類型、靜音、素材失敗、減少動態、遠端事件及演出清除；跑完整回歸測試。844×390 與 393×690 均截圖親眼檢查，文字與操作不能被擋住；本機不能跑時改由雲端 CI，沒有結果不能寫通過。
8. **交接與發布**：保存核准圖集、原音效來源、時序、方向、尺寸算法、適用範圍與測試結果；列明設計規則變更。更新版本、Build、發布說明、版本表、MANIFEST 與稽核紀錄。部署後驗證正式主選單、新局數步與主控台；未完成寫「部署後未驗證」。
