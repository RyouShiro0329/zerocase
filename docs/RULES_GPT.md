# 給 GPT／Codex 的規則（零號病例，2026-11-23 主人定案的新流程）

這是 GPT／Codex 唯一要從頭讀完的規則。設計決定在 `docs/DESIGN.md`，**只讀這次要改的那一塊**，用關鍵字搜尋。主人輪流用 Claude 和 GPT 更新，**以 Claude 為主**；版本可能是 Claude 剛發的。

## 一、開工
1. 從最新的 `main` 開新分支（`feat/…`、`fix/…`），一個任務一個分支，不要接在舊分支上做。
2. 看 `git log --oneline -5`、`更新說明.txt` 最上面。版本以 `index.html` 的 `const ZC_VER=` 為準。
3. 把主人的要求拆成清單，做完逐條對照。
4. 下面這些情況，**停下來寫 2～4 個方案給主人選，不要直接做**：新系統、改核心規則（價錢、戰鬥、警戒、善惡值、存檔）、刪內容、改劇情走向、有兩種以上合理做法、會讓舊測試失敗、新增會扣善惡值的抉擇。工具不能即時問問題時，把方案寫在回覆或 PR 裡，這次只做確定的部分。

## 二、GPT 最容易出錯的地方
- **用語**：遊戲文字和文件都用台灣繁體中文用語，不能有簡體字。常見錯誤：視頻→影片、激活→啟用、默認→預設、信息→資訊／訊息、菜單→選單、用戶→玩家／使用者、點擊→點／按、質量→品質、反饋→回饋、屏幕→螢幕、暴擊→爆擊、優化→改善、項目→專案、鼠標→滑鼠。guard 測試抓不到的也不能寫。
- **改寫太多**：不要重寫整段劇情、整個函式或整個檔案；不要改格式、縮排、引號風格，不要拆長行；不要把 `index.html` 拆成多個檔案。
- **假裝測過**：跑不了的寫「未測試（原因）」，不能寫成通過。Node 測試一定要跑。
- **自創設定**：不加新角色、新陣營、新地名、靈異事件、喪屍殭屍；不加台灣在地事物，舞台是 2038 年美國城市。A.C.R.U. 在一般文字只寫「穿黑色制服的人」。感染者是還保有大部分人類外觀的敵人統稱。腐殖的菌絲寫成鮮紅色、像血管在跳。
- **幫玩家把話說完**：選項小字不寫後果、數字、去處、時間；噪音、警戒、善惡值這類隱藏數值不寫在選項上。

## 三、改 index.html
- 所有程式在同一個 `<script>`，共用全域範圍。新增任何名稱前先搜尋有沒有撞名。
- 用搜尋找位置再局部修改，替換前確認舊字串只出現一次。
- 每個模組的第一行標題不能改（Claude 的切檔工具靠它，清單在 `tools/split_index.py`）。
- 節點的 `go`／`next` 指到的節點要存在；`c` 陣列不要在中間插選項，新選項加在最後。改旗標或存檔結構要在 `migrateG` 加轉換。
- 不要碰：兌換碼（程式只放雜湊）、Claude 的遊戲連結（artifact）、敵人立繪（只用主人的美術）、QTE 規則（只靠玩家反應）。不做跨局記憶、不做配方記錄。

## 四、測試
- 一定要跑：`bash tests/run_all.sh fast`（防弱化檢查＋全部 Node 測試，報告在 `test-results/report.json`，說明見 `docs/QA_SYSTEM.md`），Node 測試全部通過。報告裡 SKIP、NOT_RUN、ERROR 都要寫成「未測試（原因）」。`tests/guard.test.cjs` 永遠不改；舊測試只有在主人這次明確改了決定時才能改，PR 要寫出來。
- 新功能或修正補 1～3 個聚焦的測試，放在 `tests/`。
- 新增地點、事件節點、隨機事件、意外種類時，要在 `tests/helpers/env-compat.cjs` 的對照表照節點文字分類（室內／戶外、有什麼東西），不然 FAST 會失敗；新音效名稱要有檔案或合成音，不然素材掃描會失敗（2026-11-25 PR-C）。
- 瀏覽器冒煙和長路線：開 PR 後 GitHub 的「完整測試」會自動跑（`.github/workflows/test.yml`），看結果就好；不用自己再跑一次。報告與失敗截圖在那次執行的 artifact「test-results」。guard 被改，「防弱化檢查」會直接失敗。
- 改到畫面：截改到的畫面親眼看過（844×390；版面有動再加 1280×720、393×690）。
- 結果只寫通過／失敗／未測試（原因）；手機一律寫「待主人實機驗收」。

## 五、發布（照順序）
1. 遊戲文字有新字才跑：`pip install fonttools brotli`，`python3 tools/make_font_subset.py`；字數沒變就還原 `fonts/`。
2. 升版：`python3 tools/release.py patch|minor|major`（修正、數值、文字＝patch；新系統、新內容＝minor）。它會改 ZC_VER（版本、Build +1、台北時間）和字型網址 `?v=`，印出 index.html 的 SHA-256。**不要手動改版本號。**
3. `更新說明.txt` 最上面寫一段（改了什麼、測試結果、未測試和原因、碰到哪些主人原本的規則）；`docs/VERSIONS.md` 表格最上面加一行（commit 欄寫「見 commit 訊息」）。
4. 一個 commit（訊息用「v版本：」開頭，之後靠它找這一版），push，開 PR。PR 說明短：版本／Build、改了什麼、測試結果、未測試、有沒有碰到主人原本的設計規則。
5. **不要自己合併**。主人說可以才合併（一般 merge，不用 squash，不然 commit 訊息會找不到）。

## 六、回報給主人
- 中文、短。改了什麼、測試結果（通過／失敗／未測試＋原因）、有沒有碰到原本的設計規則、待主人決定的事。手機一律「待主人實機驗收」。
- 攻擊特效（穿刺、弓弩、槍擊等）的展示與整合流程，照 `docs/DESIGN.md` 的「攻擊特效的展示、確認與整合」。
