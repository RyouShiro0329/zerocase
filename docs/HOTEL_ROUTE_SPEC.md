## 1. 設計原則
1. **只往前**：走過的地點、做過的選項消失；不顯示已搜過／還沒進去。
2. **每一步是一張卡**：固定／隨機／抉擇／搜索／分岔（見 2）。
3. **隨機有邏輯**：事件牌標 `at`（地點）、必要時標夜／日與旗標條件；不符合就不進牌堆；牌堆空就直接過。
4. **抉擇寫旗標**，旗標改變後面卡與出口。
5. **時間壓力**沿用 `G.clock`、警戒 `alarm`；搜索與抉擇會花時間（`t:'q'|'m'|'l'`）。
6. 旅館內**不出現商人**；停電中的旅館也不放休息點（可睡的只有 H2 宿舍，那是抉擇）。

## 2. 卡的種類（資料格式建議）
```
ROUTE = { 地點id: {
  entry: 節點id,             // 固定入口卡（沿用現有 N[...] 劇情）
  draw: {n:1~2, at:地點},    // 隨機牌堆（EVPOOL 事件，at/需要的旗標過濾）
  search: {n:2, items:[...]},// 搜索點，次數 = max(2, 人數)，用完整個消失
  choice: 抉擇節點id | null, // 有真正差異的抉擇
  fork: [ {l, to, need?, hide?, once?} ]  // 出口分岔，選一條，其他錯過
}}
```
- 引擎面：旅館不再走 `ZONES`/hub/room；改用「單向路線」：進入節點後只提供該卡的選項；`go` 之後把已走過的 id 記在 `G.route`，不得再進入（`enterNode` 擋掉並導向該路線的下一張卡）。
- 舊存檔（沒有 `G.route`）要能載入不壞：視為當前節點之後都可前進。
- 單人、多人都要能走；多人 `voters()` 投票照舊。

## 4. 抉擇（真正有差）★ 草案，細節給主人調整
> 全部抉擇：選項寫旗標；後面至少一處（卡、出口、NPC 生死、物資）依旗標改變。

**D1 三樓走廊：拖行聲逼近（停電的第一夜）**
- (a) **用消防斧在走廊口守住**：打一場戰鬥，贏了 `corr_held`＝走廊的人（306 接送人員的同伴）有機會活到之後的廣播/情報；輸或逃＝他死。
- (b) **把聲音引到 302 的倉庫**（製造噪音、關門）：`corr_lured`＝拖行聲轉向、警戒 +1、少一場戰鬥，但 302 的人被留下（NPC 死）。
- 影響：`corr_held` 之後大廳／停車場會遇到他幫你開門（少一場戰鬥或給情報）；`corr_lured` 沒有。

**D2 廚房冷凍庫（F2x）**：圍裙寫「不要開。拜託。」
- (a) **拆開拖把柄開門**：裡面是被反鎖的員工與住客，一部分已感染 → 戰鬥；活下來的有 1~2 人 `freezer_open`＝**他們指路（地下室鐵門的卡位置，`gasnote` 與 `labpw` 線索）並在大廳幫忙**。
- (b) **不開**：安全，但他們死在裡面；`freezer_shut`，**少一條線索**，大廳少人幫忙。
- 差異：真結局入口線索、大廳戰鬥難度、一條 NPC 線。

**D3 洗衣房宿舍：凱文（`carkey`）**
- (a) **等凱文回來**：凱文帶傷進來，救他（用繃帶/酒精）→ `kevin_alive`＝他給你車鑰匙(`carkey`)，並指停車場捷徑；
- (b) **鎖上門睡**：你休息（HP/SAN 回復）但凱文在門外死掉，`kevin_dead`；車鑰匙要自己去翻，停車場會碰到他變的感染者。
- 差異：休息 vs NPC 命、鑰匙取得方式。

**D4 一樓：備品間倒地的人／行李箱在動**
- (a) 救倒地的人（耗物資）→ `staff_alive`＝他帶你走員工樓梯直達停車場（跳過大廳戰鬥）。
- (b) 打開在動的箱子 → 戰鬥，內容物（`carkey` 線）。
- (c) 不碰。三者互斥，選一個其他消失。

**D5 地下設備層發電機**
- (a) **啟動發電機**：全旅館有電（`power`）→ 讀卡門可用（`END_lab` 路線）、電梯能用，但警戒 +2，大廳的感染者被燈光吸引到大廳（I1 戰鬥多 1 隻）。
- (b) **只拿配電室的東西（`mask`）**：安靜，但鐵門打不開（真結局入口需之後回訪＋條件）。
- 差異：直接影響真結局入口。

**D6 大廳**：入住簿
- (a) **帶走入住簿**（`ledger`）：之後 A.C.R.U. 線與真結局需要；多花時間、警戒 +1。
- (b) **直接走**。
